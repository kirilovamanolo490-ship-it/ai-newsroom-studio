# AI早晚报制作规范

本规范从2026年10月12日起用于每天的早晚两期；automation id 为 ai-08-20。自2026年10月13日本次调整起，任务改为“AI资讯：每2小时采集，08/20点汇总”，北京时间每个偶数整点执行。每次仍在独立新聊天中运行，状态通过工作区中的批次、生产与来源回执交接，不依赖旧聊天上下文。

## 两小时资讯与特别报道

每天00、02、04、06、08、10、12、14、16、18、20、22点触发，处理原定触发时刻之前已闭合的2小时窗口，左闭右开。例如14点处理12:00至14:00，00点处理前一天22:00至当天00:00。使用原定调度时刻，不用实际执行结束时间重算窗口。调度时刻不明确时，`tools/news_batch.py plan` 可推断最近已闭合偶数整点，但必须保留 inferred 标识并检查漏批，不能声称它是调度器提供的时间。

每批先形成一份简明资讯流：已核实消息、来源、原发布时间、关键事实和待核线索分开保存。普通时点必须制作图文与原创短视频；遇到重大模型/产品发布、重大价格权益或政策变化、有充分材料的特色主题，单独制作“AI快讯 / 紧急报道 / 特别报道”。标题明确具体事件，有原文与真实图片、已知事实和相关背景；证据不足留待核，不因两小时到了就把普通消息拔高成“紧急”。没有可靠新增也须保留真实采集回执与覆盖缺口，不硬凑报道。

批次工作文件保存在 `research/news-batches/YYYY-MM-DD/HH00/`，日期与HH按窗口结束时刻命名。`batch.json`、原文核验、素材和分流记录在此交接；读者可看的资讯另存到 `research/evidence/bulletins/YYYY-MM-DD/HH00/index.html`，特别报道放同批次的 `special-事件标识/`。普通时点制作两小时短版；08/20点仅制作12小时综合版，不再另做06–08或18–20短视频。每天10条短版加2条综合版，共12条。两小时报道已经出现的消息，仍可在对应12小时综合资讯中合并总结，不因已做特别报道而被整期排除。

每个新批次首次执行使用 `research/.venv/bin/python tools/source_watch.py --force` 检查所有已启用自动入口，避免旧6/12小时间隔跳过来源；不修改或启用受限的manual入口。保存实际run_id，失败分页使用 `--only <来源ID>` 续抓，不能在恢复同批时重复全量读取。采集锁冲突时保留pending状态，稍后复查真实回执；不得把没有启动或返回失败写成已采集。每批同时审阅原始snapshot的items与变化事件，首次基线也要按本批窗口筛选。

`batch.json` 的最小契约如下（示意值不是一次真实采集）：

```json
{
  "schema_version": 1,
  "batch_id": "2026-10-13/1400",
  "window_start": "2026-10-13T12:00:00+08:00",
  "window_end": "2026-10-13T14:00:00+08:00",
  "status": "reviewed",
  "source_run_ids": ["实际采集run_id"],
  "coverage_gaps": [],
  "stories": [],
  "special_reports": [],
  "pending_editorial": []
}
```

只有完成内容分流才可标记reviewed；它仅表示本批编辑已审阅，不证明全部来源覆盖或媒体成品已验收。`source_run_ids` 必须指向真实存在的采集回执；没有新闻也必须有采集证据。`stories` 每项至少有 `event_id`、`content_version`、`title`、原发布 `url` 和带时区的 `published_at`，发布时间必须在本批窗口内。附上source_id、snapshot路径、first_seen_at及核验结果。content_version使用已核事实内容指纹，同事件多来源使用稳定event_id；不要以标题当唯一身份。旧消息修订、无可靠时间及窗口外迟发现线索进入pending_editorial，分别保留修改/生效/首次发现时间与归属窗口；待核队列跨批继承，不丢弃。

### 六批汇总顺序

| 综合资讯 | 六个批次的结束时刻（北京时间） | 汇总窗口 |
| --- | --- | --- |
| 08:00早间资讯 | 前日22:00、当日00:00、02:00、04:00、06:00、08:00 | 前日20:00至当日08:00 |
| 20:00晚间资讯 | 当日10:00、12:00、14:00、16:00、18:00、20:00 | 当日08:00至当日20:00 |

08/20点在同一次运行中，先完成第六批，再读取六个固定批次，最后制作综合资讯；不要另开同时抢跑的汇总任务。8点是最后一批开始采集及汇总的触发点，真实成品在采集、核验、渲染完成后产生，不承诺8点零分已完成成片。不要把六个简报直接拼接：合并同一事件、更新最新进展、去掉重复表述，重新组织本期重点与解说。

```sh
research/.venv/bin/python tools/news_batch.py plan --scheduled-for 2026-10-13T20:00:00+08:00
research/.venv/bin/python tools/news_batch.py bundle --date 2026-10-13 --edition evening --output research/editions/2026-10-13-evening-input-bundle.json
```

plan只计算批次与六个输入位置，不采集也不制作。bundle只检查、汇集已经落盘的已审候选，不代替事实核验或成品验收。退出码2表示缺批、非法回执或来源覆盖缺口；读取其missing/invalid/gap信息，只补有缺口的部分。补查可读取既有真实runs/snapshot并按原发布时间归批，记录实际采集时间及backfilled=true，不伪造过去每两小时已成功运行。上线首期同样如此。补不齐可制作已核内容并明确coverage_status=partial与缺失批次，不能声称六批齐全，也不能以“无新闻”结束。视频/网页的verified与来源coverage_status分别登记。

综合资讯保存input-bundle及所用批次路径、run_id、内容版本、去重和合并说明。跨批按event_id+content_version去重，同一事件不同版本保留进展供编辑合并；综合资讯是否已完成仍以production-state及内容指纹判断，采集seen、批次已审和特别报道完成都不等于整期已制作。已完成期次不因切换新流程而重制。

## 期次与时间

以Asia/Shanghai为准，每天08:00触发早报，覆盖前一日20:00（含）至当天08:00（不含）；20:00触发晚报，覆盖当天08:00（含）至20:00（不含）。延迟执行也保持固定窗口。最新已经闭合的窗口：20点以后是当日晚报；8至20点是当日早报；8点以前是前一日晚报。对照已有生产回执补查缺失期次；同一期已verified且输入内容指纹一致则复用，不重复计费或重复通知。

先检查原始发布时点；发布时间、修改时间、生效时间、首次发现时间、截图采集时间分别记录。网站sitemap lastmod不能当新闻发布日期，旧公告在窗口内新发介绍/周报要明确是介绍或回顾。仅在窗口内被发现但没有可靠发布时间的内容保留为待核线索。08:00整的消息属于晚报。早晚各12小时由tools/edition_contract.py校验，网页和视频使用同一内容指纹。

## 采集与核验

先读sources/来源库维护说明.md，按上述两小时流程采集；08/20点汇总复用六批回执，只对缺口补查。退出码2是部分覆盖有缺口；保留水位、去重和翻页游标。可以用--only对未完成分页继续读取，不整批反复跑。按run_id审阅全部未审阅report.json，保存候选分流结果并更新review-state，未核批次不能因为latest快照替换而丢失。每期同时按窗口过滤runs内原始来源快照的items，而不只看changes列；首次基线的items也可包含尚未报道的窗口内消息。以原发布URL与内容版本对照已完成期次去重，采集seen水位不等于编辑已报道。

用最新橘鸦日报补漏；日期变化、新一期或修订时刷新滚动近月链接、回查新目录/账号。X归真实作者，网页归实际包含多篇的目录；媒体、社区、个人与官方分开。已识别X账号应通过connect_library_watch接通并首次建立基线，不将旧贴推成新增。Linux.do AI标签目录通过网页工具可读，常规HTTP403，按manual_watch_only留出处和访问限制，每期可以用网页工具复核；不能称全自动接通。

选取有价值的模型、工具、应用小功能、权益、产品更名/停用、行业合作、人物互动与趣闻。使用媒体线索时找原发布者。人物争论需保留上下文和双方出处；用户体验按“用户分享/发布者表示”归属，不变成独立实测。至少每条有真实截图；未取得的图片不能标取得。截图来自实际浏览器页面或实际X官方嵌入，正文折叠、视频未显示等据实记录；不拿API文字重绘成假推文。原图和视频也保存原资源、作者、SHA与素材类型。

## 截图验收

截图保存后必须打开实际输出图片逐张检查，不能仅凭接口返回成功或图片尺寸判完成。检查左侧头像/作者、完整卡片左右边缘、正文、配图/视频预览、发布时间及底部是否被截断。X嵌入正文有Show more时记录折叠，原始全文另核；“卡片完整”不写成“全部正文可见”。

本机浏览器在区域超出可视高度时会发生裁切偏移；可视浏览器窗口的缩放也可能使截图坐标与页面CSS坐标不一致。原帖区域截图使用经过回归检查的稳定采集画布，确认卡片完全位于视口内，再仅传clip；不把fullPage和clip叠加，也不对已经裁切的图片重复裁切。临时截图回归画布1280×1200用于避开已证实的越界截取问题，完成后重置。保存图片的实际像素尺寸应与预期区域一致，明显不符则不得覆盖已验收素材。

截图前确认可见图片complete且naturalWidth>0，头像灰占位、视频预览黑占位或图片未加载时保留未完成状态。加载中的文件不能记已验收；可重新获取实际页面，但不能用原图覆盖进推文UI冒充真实截图。原始高清图表与原视频封面另存，网页提供打开原图入口，成片优先使用这些原资源。小截图不能通过反复放大代替高清素材。保存SHA、真实采集时间、截图范围、加载回执与目视检查结果。

## 简洁报道与封面

V8封面参考橘鸦“左侧单条主新闻、右侧干净大图标”的表达。日期（年月日）与栏目名放左上，左侧主体只留一条本期最重要的新闻，通常2至3行；右侧使用2至4个与本期消息相关的真实品牌标识，大图标、正确比例、足够留白。不再六条列表、两列三行、密集表格线、重复副标题或装饰性小字，不用模型重画Logo。主体标题直接表达产品和关键变化，克制准确；预告与正式发布、重置完成与未来加量等区别不能省略。头条依据已核事实、影响范围、时效和本期受众价值选择，不固定某家公司。

短版栏目叫“AI此刻”，日期使用“YYYY年M月D日”，必要时小号“16:00 更新”；不以“14点至16点资讯信息”作主标题。早晚综合版仍叫AI早报、AI晚报。精确起止时点留在网页详情和数据库字段。`presentation`需写version=8、issue_title、lead_story_id、cover_headline（可换行）、cover_brand_ids；短版加issue_time。lead_story_id必须属于本期，cover_brand_ids必须对应本期真实品牌；单条封面头条不改变正文栏目顺序。cover_story_ids仍按正文顺序登记供导读与网页重点使用。

解说直接说发生什么、关键数字、动作及来源归属。保留有意义的订阅/API范围、投票/已生效区别和个人案例归属；删去冗长的个人分析、反复不确定提醒及无关因果推论。核验边界放网页折叠区。每条有对应品牌素材，优先本地缓存；缺失先核官网/官方仓库/App Store原资源后入库。Logo、App图标、favicon、组织头像、官网配图按真实类型登记，不让模型重画Logo。

正文固定上下导航与短主标题，中间按真实图片/表格/短片的形状排版，不统一给图片添加背景框。分镜数据来自本期，不硬编码昨天新闻。新生成旁白继续用已有Seed TTS 2.0 Vivi自然女声适配器，每场连续合成并用服务真实时间戳对齐字幕；API失败停在具体缺口，不换机械系统声。只有更正文案时才用--refresh-changed，并保留旧回执。

新期presentation.version使用8（正文沿用V6自适应布局，封面采用单条头条与右侧大图标）。不得连续将每条新闻套入“左文字右图片”同一分栏。编辑narration-draft时依据材料选scene.visual.layout：context展示已经核验的上下文数字；workflow展示原文中的3至4步流程；feature-board整理实际功能；source-focus放大原帖；event结合活动原海报与真实日期/奖金；cinema放大原短片并展示发布帖；case按讲述阶段切换案例与双方原帖；settings结合真实界面与选项说明。steps、metrics、labels、cover_title和recap_title只改写本期已核内容；金额、日期与时区须来自本期证据。不为填空白增加猜测或装饰。缺少专门布局时按原图比例、素材类型和场次回退，不假造UI或推文。段落预览须包含后续字幕阶段，确认换画面和两行字幕均与导航分开；回顾按本期板块列出消息，不重复空泛分析。

## 隔离产物与制作命令

早报数据在research/evidence/YYYY-MM-DD/morning/，晚报在evening/。10月10日至12日实验产物已按用户2026年10月13日要求清理，不再作为公开期次。对应report.json、narration-draft.json须先完成编辑和时间校验。

```sh
research/.venv/bin/python tools/produce_daily.py --date YYYY-MM-DD --edition morning --narration research/evidence/YYYY-MM-DD/morning/narration-draft.json --render-video --preview-frames
```

晚报替换edition和目录为evening。该命令只把已审核数据制作为网页与原创视频，不自动把原始候选当成新闻。Seed输出和manifest在当期voice-v2/，仅写入当期回执。完整源视频和引用片段保留归属；不复用橘鸦成片作为自己的视频。

检查实际MP4、PNG封面、字幕时间、章节点、截图查看器与手机布局；检查素材hash和音轨再把own-video状态从rendered改成verified。生成production-run、verification及源材料回执。无可靠新增则保存window-no-news.json及覆盖缺口，不用旧新闻凑视频。早晚完成后在当次执行聊天中提供简短结果链接，不逐条重复发送普通噪声。

凭据只在现有脚本内部读，不打印或写入公开目录。禁止Firecrawl、充值、安装扩展。

## 平台发布状态与后续动作（2026-10-15）

本地视频完成既有完整播放、音轨、字幕、章节和画面验收后，才进入外部平台提交。每个目标平台独立记录；只提交当前已绑定的平台，未绑定平台跳过且不阻塞其它平台。上传器明确返回 `submitted_unverified` 且 `exit_code=0`，或平台返回 `processing` / `public`，即代表该平台提交流程完成。成功回执后不例行打开创作者后台核验，不切换账号或重新登录确认，也不重复上传。准确保留平台回执状态；不得将提交成功、处理中或平台公开回执臆写为 `independently_verified_public`。失败、账号无效、结果含糊分别保留为独立状态；仅这些状态需要后续动作，并按回执采取有针对性的处理。每个平台的状态不影响其它已绑定平台的提交。

上传前账号检查须区分真实登录失效与临时页面故障。`Page.goto` 超时、网络连接错误不能直接判为账号过期；通过既有适配器最多重试一次，仍失败时记录 `account_check_transient`，保留原登录信息，不要求重新绑定。2026年10月15日10点小红书失败即由页面加载超时误分类引起，同一份登录信息复测有效。实际上传一旦产生持久提交回执，仍不得因为超时或结果不明而盲目重传；这个有限重试只用于上传前的只读账号检查。

## 网页展示与旧实验清理

2026年10月13日用户要求公开站点只保留13日早报，并删除前期实验页面和旧设计产物。生产状态只登记现存成品；旧实验消息的最小原URL/内容版本身份保存在research/editions/reported-history.json供去重，不作为页面期次。原始采集snapshot、水位、来源库和品牌主缓存继续保留。

网页只使用build_report.py调用build_edition_report.py。页面顺序为本期标题和摘要、原创视频、消息正文、来源说明；不显示实验日期选择器、重复目录、无关品牌画廊或制作流程字段。web-editorial.json可优化标题和摘要，但事实必须来自已核report.json。原帖、高清素材和核验细节按消息展开，网页改版不自动重制视频或重复TTS。网页新版另存web-verification.json，并登记production-state的web_revision。

## 08/20 必须交付完整视频（2026-10-13 用户明确修订）

每个08:00早报和20:00晚报都必须有正常可播放的完整原创MP4。图文、封面、单独开场、仅渲染成功都不算整期完成；媒体验收与来源覆盖仍分别登记。其它10个偶数整点也必须交付两小时短视频；每天12个视频时点，不增加第13、14条固定视频。

在进入早晚报时先对既有语音服务做一次短语音预检，与最后一批来源采集分开记录，尽早发现依赖故障：

```sh
research/.venv/bin/python tools/synthesize_seed_voice.py --preflight --output research/voice-preflight/YYYY-MM-DD-evening
```

预检只证明当时可调用，不替代全部场次的实际合成。成功场次继续使用内容指纹缓存；短暂网络、限流或服务端故障有限退避重试。HTTP403和资源错误45000030记录为resource_not_granted，不再无差别重试，也不能误报成没有内容或已完成。仅用户已批准且经过试听验收的备用自然女声可以自动切换；当前未批准的新声线不能擅自替换。不能用机械系统声、静音幻灯片或旧期视频冒充正常新一期成片。

`tools/produce_daily.py --edition morning|evening|briefing` 默认必须制视频。`--web-only-maintenance` 仅维护图文，状态为maintenance_only，不是早晚报完成。相同报告指纹的已验收视频通过门禁后可直接复用。实际播放、声音、字幕、章节点和图像检查通过后，保存与报告指纹及MP4哈希一致的verification.json及own-video.json，再运行：

```sh
research/.venv/bin/python tools/produce_daily.py --date YYYY-MM-DD --edition evening --verify-only
```

完成门禁要求完整当期视频、真实文件哈希、1080p画面、音轨、与全部场次一致的时长及全程播放验收。未通过不得登记completed。所有失败阶段即时写入production-run，成功缓存不丢弃，错误记录不包含凭据和上游原始响应。

即使本期没有可发布新增，也必须制作简短状态视频，不能取消08/20成片。先保证真实六批均已审阅，再执行`tools/prepare_status_edition.py --date YYYY-MM-DD --edition morning|evening --output-dir research/evidence/YYYY-MM-DD/期次`。该模式保留stories为空，使用status_only报告及真实覆盖说明；覆盖partial只能说暂无已核新增，不能据此宣布没有新闻。不得用旧新闻填时长。既有已验收期次不能覆盖。

每次独立调度都检查production-state.in_progress及review-state.pending_productions，在当前新聊天恢复最近未完成早晚报的视频阶段；这属于原期次续制，不是提前制作新期次。原固定窗口、输入指纹与成功场次缓存保持不变，不重复全量采集，不使用heartbeat、不转发固定旧聊天。只有完整视频通过验收才把期次移入completed。需要外部恢复授权的问题应给出具体错误码与所需操作，保留待完成状态，不能把图文就绪当作交付成功。

## 栏目、导读与视频顺序必须一致（2026-10-13 用户反馈，仅约束后续制作）

整期的顺序只采用一个来源：`presentation.groups`从左到右的栏目顺序，再按各栏目`story_ids`的条目顺序展开。旁白脚本、视频正文、底部导航、章节菜单、网页栏目和回顾都必须采用这一展开顺序。导读/封面重点可以选取部分条目，但这些条目的相对顺序必须与正文一致。

例如，顶部栏目为“模型与设备 → 工具与用量 → 公司与数据”，视频必须在导读后先讲完模型与设备，再讲工具与用量，最后讲公司与数据，再回顾；不能第一条跳到公司与数据，也不能在栏目间来回穿插。如果策划阶段希望突出某一栏目，需在制作前统一调整栏目、导读与脚本，不能只单改正文播放顺序。

`produce_daily.py`在语音合成前校验旁白顺序；`prepare-episode.py`使用严格列表顺序检查，并将封面重点按同一顺序排列；新成片的`navigation-groups-v1`完成检查再核对栏目、场景和章节。只比较条目集合不足以通过验收。
